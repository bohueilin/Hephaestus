# v0.2 direction — options considered and recommended scope

**Status: design proposal, not a ratified design.** No measurement was taken for this
document. Nothing in v0.1 changes: the limits 1.10 and 0.10, the v1 and v2 methodologies,
the criteria file and its pin, probe 2, series 1, and every published sentence stand as
they are. Three owner decisions (section 8) are open; a full design package and its
pre-registration follow those decisions, and no schema-3 measurement may be taken before
that pre-registration is ratified and committed.

Everything below is derived from public `main` at commit
`77a3900427588a4ee46d9763c893d8c8128c7013`; file references are to that tree.

## 1. Why a v0.2 exists

Three facts in the code decide the direction.

- **Per-shape performance is not measured today.** The only steady-state timed series
  runs on the primary input case (`measure.py:371-379`). The other pinned shapes of
  `dynamic_batch_text` each receive one single-shot compiled call in the compile sweep
  (`measure.py:361-366`); the gate counts and orders those samples but never reads their
  magnitude (`gate.py:952-970`). Recompiles are a bundle-wide total with no per-shape
  attribution. `DESIGN.md:147-150` names this gap as the v0.2 item.
- **The versioning discipline for an additive release already exists.** Methodology
  dispatch is an exact-integer branch on an optional `schema_version` key whose absence
  means v1 (`gate.py:188-196`); a v3 slots in beside v2 at each dispatch site without
  touching v1 or v2 text. Criteria are byte-pinned (`criteria.py:12`), so a new criterion
  can only ever be a new file with a new pin.
- **One tripwire is missing.** Only methodology-v1 bundles are committed under
  `tests/data/`. Nothing in the public tree can prove that a gate admitting schema 3
  preserves methodology-v2 verdict bytes. A committed v2 archived bundle is a
  prerequisite for any dispatch change.

The LLM direction is deferred: with nine catalog entries across four workloads, the
scripted policy already walks every candidate to the first `PROVEN`, and each child's

to that catalog can only reorder a walk of nine, and its smaller variants are scaffolding
that add no protection the tests do not already assert.

## 3. Recommended v0.2: the dynamic-shape lab, smallest coherent scope

**In scope**

- Methodology `schema_version: 3` = the frozen v2 settings (64 repeats, cross-parity
  position-matched pairing, alternating `eager,A,B` / `eager,B,A` schedule, the frozen
  bootstrap) plus, after the unchanged primary block, one additional interleaved block per
  non-primary pinned case of `dynamic_batch_text`, each through the identical estimator
  (`measure.py:529-592`). The primary block keeps its position and meaning, so
  `perf.speedup_proven` and the noise-floor check are semantically unchanged.
- Evidence as new keys only, no new files (bundle topology is a closed set,
  `gate.py:539-567`): per-case steady-state series in `timings.json`, per-case floors and
  block order in `methodology.json`, per-sweep-case recompile attribution in
  `dynamo_report.json`, admitted only when the methodology schema is 3.
- A `shape.*` finding family emitted only under schema 3 and appended after the existing
  findings, so v1 and v2 verdict bytes cannot move. Informational; never verdict-driving.
- Per-sweep-case recompile attribution recorded from the existing compiler-evidence
  snapshot (`torchbind.py:323-325`) between sweep calls; recompiles observed after the
  sweep reported as an explicit unattributed count.
- A parent-level `frontier.json` over the three existing `dynamic_batch_text` catalog
  entries (`catalog.py:290-309`), verified as a pure function of the child bundles in the
  style of the agent search tree (`search.py:221-247`).
- One pre-registration, ratified and committed before the first schema-3 measurement.

**Out of scope**

- Shape weights or distributions: all four pinned cases hold exactly 48 tokens
  (`workloads/dynamic_batch_text.py:43-48`), so a weight vector could only express
  preference among equal-volume shapes.
- Any new workload or new tensors: forbidden by the workload digest pin
  (`evidence_contract.py:12-19`; `gate.py:52-57`).
- Any new criterion, any edit to `gates/default.yaml`, any change to the meaning of 1.10
  or 0.10.
- Any change to `run`, `agent optimize`, `demo-planted-regressions`, or `aa-test`, which
  stay at methodology v2.

## 4. Protocol decisions to freeze in the pre-registration (recommended answers)

1. **Block order.** Sequential: primary block exactly as v2, then each non-primary case as
   its own block. Disclosed in advance: per-case differences are confounded with time
   order on this host and are reported as a table, never as "shape X is faster than
   shape Y." Rationale: the only order that leaves the v2 estimator textually reusable per
   block.
2. **A per-case floor at or above 0.10.** Marks that case's `shape.*` finding OPEN and
   leaves the verdict to the primary series; the primary-series rule is not edited. The
   frozen 0.10 keeps an identical meaning while the lab does not become a fourfold
   invalidation lottery.
3. **The frontier.** Informational findings plus a verified parent file, not a criterion.
   No rule about per-shape frontiers can be pre-registered honestly before one exists;
   "as gate criteria" is deferred to a later pre-registration that cites the v0.2 outcome.
4. **Recompile attribution.** Recorded between sweep calls, not reconstructed offline from
   two unrelated clocks.

## 5. Prerequisite before any dispatch code changes

Commit a real, privacy-scrubbed methodology-v2 archived bundle under `tests/data/` with an
archive-bytes test in the pattern of `tests/test_methodology_archive.py`. It must come from
a preserved archive, never be synthesized, and pass the same privacy rule as the v1
fixtures.

## 6. Constraints v0.2 preserves

Policy proposes, environment executes, verifier evaluates, gate decides, trace proves;
capability is not permission. Machine-local Apple Silicon CPU evidence only; no GPU, CUDA,
Triton, production-safety, or cross-machine claim. The optimizer stays an inert
closed-catalog policy. Bundles stay hash-manifested and offline-verifiable. Methodology v2
stays at 64 paired effects. The thresholds stay 1.10 and 0.10. Probe 2 and series 1 stay
published failures, unreinterpreted. Any protocol is frozen before data. Calibration
traces stay analysis-grade. The host is the runtime configuration recorded in the
committed evidence headers; any change is a new measurement reported beside, never in
place of, existing results.

## 7. Claims v0.2 may add, only under its own ratified pre-registration

Every v0.2 number is machine-local evidence from this host and runtime configuration.
Every v0.2 verdict is decided by the primary-case series under the unchanged v0.1
criteria; `shape.*` findings never drive a verdict. Per-shape results are four pinned
shapes of equal token count on one workload in a fixed block order within one run,
reported as a table. The frontier is a description of three catalogued configurations on
those shapes on this host, not a criterion and not a recommendation. Recompile
attribution counts are observations of the pinned Torch build between sweep calls. No
v0.1 bundle is invalidated. The pre-registration fixes its outcome sentences, including
the sentence carried if the protocol fails, before the first measurement.

## 8. Decisions required before a design package is written

1. Is the "exactly five commands" test (`tests/test_cli.py:92-118`) a frozen authority
   boundary, or a v0.1 scope statement to be amended for a dedicated `shape-lab`
   orchestrator? If frozen, the lab must run through `run` with a methodology flag plus a
   separate read-only assembly step.
2. Is a frontier over the four existing equal-token pinned shapes the intended experiment,
   or is a genuine batch or sequence size range required? The latter is a new frozen
   workload with its own digest, criteria rows, catalog entries, and pre-registration,
   roughly doubling the lane.
3. May v0.2 ship the frontier as informational findings plus a verified parent file,
   deferring `DESIGN.md:149`'s "as gate criteria" to a later pre-registration that cites
   the v0.2 outcome?
